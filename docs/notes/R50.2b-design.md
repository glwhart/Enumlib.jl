## 2. The math, in Enumlib's representation

In the dset-mapping writeup, the action on `(d_i, g)` is

```
g' = T A⁻¹ v_i + (T A⁻¹ N_Cartesian A T⁻¹) g       (mod SNF diagonal)
```

where `T` is the SNF left transition matrix, `A` is the parent basis, `N_Cartesian` is the rotation in Cartesian coords, and `v_i` is the lattice shift (in Cartesian).

In Enumlib, rotations are stored in **lattice coordinatse** (`SymmetryOp.R` is an integer matrix) and the precomputed `v_i` is also in **lattice coordinates** (integer vector, from R50.2a). Substituting `N_Cartesian = A · N_lattice · A⁻¹` and `v_i_Cartesian = A · v_i_lattice`, the formula collapses to:

```
g' = T · v_i + (T · N · T⁻¹) · g                     (mod SNF diagonal)
```

— **identical structure to the existing single-lattice `getPermG` formula** plus the per-(N, i) constant shift `T · v_i`. For single-lattice (n_D = 1) the precomputed `v_i = [0,0,0]` zeros out the shift; the unified path degenerates exactly to today's single-lattice behavior (L1 lock).

## 3. Implementation plan

### 3.1 New `getPermG` method

Add a method dispatching on `ParentLattice` alongside the existing legacy `LG::Vector{Matrix{Int}}` method:

```julia
function getPermG(h::AbstractMatrix, fixingOps::BitVector, parent::ParentLattice{D}) where D
    # 1. SNF of h gives the supercell's quotient group structure.
    S, L_snf, _ = NormalForms.snf(h)
    Linv = round.(Int, inv(L_snf))
    diag_S = diag(S)
    z1, z2, z3 = diag_S
    n   = prod(diag_S)
    n_D = ndset(parent)

    # 2. Supercell sites in SNF basis (G = Z/z1 × Z/z2 × Z/z3).
    GspcSites = [[i, j, k] for i in 0:z1-1, j in 0:z2-1, k in 0:z3-1] |> vec
    factor    = [z2*z3, z3, 1]                 # flat_g(i,j,k) = i·z2·z3 + j·z3 + k + 1

    # 3. For each fixing op, build the perm on n_D·n sites.
    #    Site-ordering (L3): flat_idx(d_i, g) = (i-1)·n + flat_g.
    LG  = lattice_rotations(parent)
    fixing_indices = findall(fixingOps)
    rotPerms = Vector{Vector{Int}}()
    for op_idx in fixing_indices
        N_op = LG[op_idx]
        π    = parent.dset_perms[op_idx]
        v    = parent.dset_shifts[op_idx]
        TNT⁻¹ = L_snf * N_op * Linv            # T · N · T⁻¹ (integer)
        perm = Vector{Int}(undef, n_D * n)
        for i in 1:n_D
            Tv = L_snf * v[i]                  # T · v_i (integer)
            for (g_idx, g) in enumerate(GspcSites)
                g_prime = mod.(Tv + TNT⁻¹ * g, diag_S)
                g_prime_flat = sum(g_prime .* factor) + 1
                src_idx = (i - 1) * n + g_idx
                img_idx = (π[i] - 1) * n + g_prime_flat
                perm[src_idx] = img_idx
            end
        end
        push!(rotPerms, perm)
    end

    # 4. Deduplicate rotation-induced perms (different ops can induce the same).
    unique!(rotPerms)
    sort!(rotPerms)

    # 5. Compose with the supercell translation subgroup. Translations act as
    #    (d_i, g) → (d_i, g+τ) — same shift in every dset block.
    tGrp = getTransGroup([z1, z2, z3])         # Vector{Vector{Int}}, each of length n
    perms = Vector{Vector{Int}}()
    for iR in rotPerms
        for iT in tGrp
            # Block-replicate iT across dset positions:
            full_iT = vcat((iT .+ (i-1)*n for i in 1:n_D)...)
            push!(perms, iR[full_iT])          # composition: apply iT first, then iR
        end
    end
    return perms
end
```

**Backward-compat:** the existing `getPermG(h, fixingOps, LG::Vector{Matrix{Int}})` method stays. Legacy single-lattice paths (radiusEnumeration.jl, CEdataSupport.jl) still call the LG-based method. The new method is *additive*.

### 4.6 Inactive sites within uniform multilattice?

The R50.2 design says regime B requires *uniform* allowed_labels across all dset positions. What if one site is inactive? E.g., HCP with dset position 1 binary `{0, 1}` and position 2 fixed `{0}`. That's *heterogeneous* (different allowed_labels) — regime C — and is rejected.

But what if both positions are uniformly inactive? E.g., HCP with both positions `{0}` — labels_uniform is true, but there's nothing to enumerate.

The existing validation has `is_active(site) || throw(...)` for regime A. The regime-B path falls through to this same check (using `sites.list[1]`). If site 1 is inactive, throws the same "nothing to enumerate" error. **No new code needed for this edge case.**
