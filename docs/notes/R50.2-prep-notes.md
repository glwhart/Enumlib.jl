## 1. The math (from the dset-mapping writeup)

### 1.1 Setup

- Primary lattice `L` with basis `A` (`D×D` matrix, columns are lattice vectors).
- Multilattice `M = ⋃_{d ∈ D} (L + d)` where `D = {d_1, ..., d_{n_D}}` is the *dset* (fractional positions in the unit cell).
- Symmetry operations of `M` are pairs `(N, t)`: `x → Nx + t` maps `M` to itself.
- Per HF 2009 Appendix: `t` can always be chosen as an element of `D` (no float-tolerance handling needed; the action becomes combinatorial).

### 1.2 Action of `(N, t)` on the dset

For each rotation `N` and each `d_i`, there's a unique `d_{π(i)}` and a unique lattice vector `v_i ∈ L` such that:

```
N d_i + t = d_{π(i)} + v_i
```

- `π` is the *dset permutation* induced by `N` (sends `i` to `π(i)`).
- `v_i` is the *lattice shift* needed to bring `N d_i + t` back into the first cell at position `d_{π(i)}`.
- Both `π` and `v_i` depend only on `N` (and on the dset structure of the parent), not on the supercell `H` or the labeling.

**This is the precomputation step.** For every parent rotation `N` in `parent.space_group`, precompute `π` and the `v_i`s. Cache on `ParentLattice`. The Fortran's `get_dvector_permutations` does exactly this.

### 1.3 Supercell + quotient group

- Superlattice basis `B = A · H` (where `H` is the HNF).
- Smith Normal Form of `H`: `H = L⁻¹ · S · R⁻¹` with `S = diag(s_1, s_2, s_3)`.
- Quotient group `G = L_parent / L_super` decomposes as `Z_{s_1} ⊕ Z_{s_2} ⊕ Z_{s_3}`. Order `|G| = n = s_1 · s_2 · s_3 = vol(H)`.
- Each element `g ∈ G` indexes a translate-equivalence class in the supercell.

### 1.4 The full action on `(d, g)` pairs

A site of the multilattice supercell is a pair `(d_i, g)` with `i ∈ {1,...,n_D}` and `g ∈ G`. Total `n_D · n` sites.

Under the symmetry `(N, t)` with precomputed `(π, v_i)`:

```
(d_i, g) → (d_{π(i)}, g')
```

where the new group element is:

```
g' = T A⁻¹ v_i + (T A⁻¹ N A T⁻¹) g  (mod s_1, s_2, s_3)
```

with `T` the left-transition matrix from the SNF computation. **All integer arithmetic** once you're in the SNF basis. Two pieces:
- **`T A⁻¹ v_i`** is a per-(N, i) constant shift (depends on dset position).
- **`(T A⁻¹ N A T⁻¹) g`** is a matrix action of N on the group element (after change-of-basis to SNF).

### 1.5 Stabilizer + supercell permutation group

A `(N, t)` symmetry is in the supercell's stabilizer if and only if `N` fixes the superlattice (`N L_super = L_super`, i.e., `H⁻¹ N H` is unimodular integer). **Important:** the criterion uses only `N`, not `t`. The dset action is automatic once `N` is in the stabilizer.

For each stabilizer op `(N, t)`:
- Apply the per-site action above to every `(d_i, g)` pair → get a permutation on `n_D · n` sites.

Compose with the *supercell translation subgroup* (acts as `(d, g) → (d, g + τ)` for `τ ∈ G` — dset position unchanged, group element shifted):
- Full perm group cardinality: `|stabilizer| · n` (translations are always non-redundant since they're free in G).

## 2. Algorithm (HF 2008/2009)

### 2.1 HF 2008 (single-lattice, n_D = 1)

Six steps:
1. Generate all HNFs of volume `n`.
2. Reduce HNFs by parent point group → symmetry-inequivalent HNFs.
3. SNF of each surviving HNF → quotient group `G = Z_{s_1} ⊕ Z_{s_2} ⊕ Z_{s_3}`.
4. Generate all `k^n` labelings of G (as base-k integers in a perfect hash).
5. Eliminate duplicates: (a) incomplete labelings, (b) translation duplicates, (c) label-exchange duplicates, (d) super-periodic labelings — all O(N) scans.
> In the original papers, we eliminated label-exchange duplicates, as equivalent under a particular mathematical definition. But most material scientists don't want to eliminate these---they are distinct materials, different concentrations. So it became a user option in the original fortran code. *Not* eliminating the label-exchange duplicats should be the default in this code. We should have lots of tests comparing the old and new code under this option to make sure everything is working.

6. Remove label-rotation duplicates via Eq. 3 (induced permutation on G, no geometry).

### 2.2 HF 2009 (multilattice, n_D ≥ 1)

**Same algorithm with `n_D · n` sites instead of `n`.**

- Step 3: SNF still gives `G`; quotient structure unchanged.
- Step 4: `k^(n_D · n)` labelings, indexed as base-k integers over the larger space.
- Step 5: same four eliminations, on the bigger labeling space. The orbit operations act on `D × G` via the §1.4 formula.
- Step 6: same.

Crucially, HF 2009 doesn't introduce a new algorithm — it just expands the labeled set from `G` to `D × G`. The orbit math is identical.

## 3. Site-ordering convention

The Fortran (`get_rotation_perms_lists`, line 587) uses **"dset blocks"**:

```
flat_idx(d_i, g) = (i - 1) · n + g_idx
```

i.e., first `n` flat indices are dset position 1 (all `n` group elements at `d_1`); next `n` indices are dset position 2; etc.

**Decision: Enumlib.jl matches the Fortran convention.** This enables direct cross-validation of permutation group output and labeling counts.

### 3.1 Single-lattice as a degenerate case

When `n_D = 1`, `flat_idx(d_1, g) = g_idx`. Matches the existing single-lattice convention exactly. No special casing needed if we route everything through the multilattice path.

**Design implication:** the §6 design doc should consider whether to *unify* the code path (one `getPermG` that handles any `n_D ≥ 1`) or keep a separate single-lattice fast-path. Trade-off: code simplicity vs preserving the well-tested single-lattice path.

> We should usually aim for code simplicity. Only in the case of big performance loss should we consider two branches rather than a single branch.

## 4. Stabilizer subgroup determination

### 4.1 Criterion

Identical to single-lattice: a parent rotation `N` is in the supercell stabilizer iff `N` fixes the superlattice. **The dset action does not enter this criterion.**

The Fortran's `get_sLV_fixing_operations` (line 1059):
```fortran
if (is_equiv_lattice(rotLat, origLat, eps)) then
```

This is the same `R H ≅ H R'` check Enumlib.jl already does in `getFixingOps`.

### 4.2 What needs to change in Enumlib.jl

`getFixingOps` currently takes `lattice_rotations(parent)` (just the `R` parts of `parent.space_group`). For multilattice, the stabilizer is *still* determined by these rotations. **No change needed to `getFixingOps`.**

What changes: the *consumption* of the stabilizer rotations downstream — instead of building a length-`n` permutation, we build a length-`n · n_D` permutation using the (π, v_i) precomputation.

## 5. Super-periodicity

### 5.1 What the existing code does (single-lattice)

A labeling `c : G → {0, ..., k-1}` is super-periodic iff some non-identity `τ ∈ G` (a translation in the supercell's translation subgroup `T = Z_{s_1} × Z_{s_2} × Z_{s_3}`) satisfies `c(g + τ) = c(g)` for all `g`. Currently dropped by default (HF 2008 step 5d).

### 5.2 Extension to multilattice

Translation subgroup `T` acts on `D × G` as `(d_i, g) → (d_i, g + τ)` — dset position **preserved**, group element shifted. This is the natural extension; doesn't mix dset positions.

A multilattice labeling `c : D × G → {0,...,k-1}` is super-periodic iff some non-identity `τ ∈ G` satisfies `c(d_i, g + τ) = c(d_i, g)` for all `(d_i, g)`.

**Structurally identical to single-lattice** — same check, just on the bigger labeling. The existing `getUniqueColorings`'s super-periodicity loop should work on the extended labeling vector unchanged, as long as the translation permutations are constructed correctly (i.e., as `(d_i, g) → (d_i, g+τ)` not mixing dset positions).

### 5.3 Pólya / Möbius (count_inequivalent)

The §4.2 digest didn't address Möbius inversion for multilattice — flagged as open. After this prep:
> I don't remember/understand what Möbius inversion is. Can you give me a short primer? In the context of this enumeration problem?

The translation subgroup `T` doesn't depend on n_D — it's purely determined by SNF. The aperiodic-count formula

```
N_aperiodic = (1/|G|) · Σ_g Σ_{H ⊆ T} μ_T(H) · |fix(g) ∩ fix(H)|
```

(chunk-7 implementation) holds on the bigger labeling space `D × G` — the joint-orbit partition becomes a partition of `n · n_D` sites instead of `n`. The math is unchanged; the per-iteration cost is `O(n · n_D + |H|)` instead of `O(n + |H|)`. **Extends cleanly.**

## 7. Current Enumlib.jl state

### 7.1 What works

- `ParentLattice(A, dset)` with multi-element dset constructs correctly. Cached `space_group` includes the multilattice operations (R + t pairs).
- `getSymInequivHNFs(n, parent)` works on multilattice parents (HF 2009 step 2 — superlattice-shape enumeration is rotation-only, doesn't depend on dset).
- `Supercell(hnf, parent)` builds without error on multilattice parents.
- `getFixingOps(hnf.matrix, lattice_rotations(parent))` correctly identifies the stabilizer subgroup.

### 7.2 What's silently wrong (the R50.2 surface)

- `Supercell.permutation_group` is computed via `getPermG(hnf.matrix, fixingOps, lattice_rotations(parent))` — **single-lattice only**. Verified by experimental probe today: HCP and diamond at n=2 produce a perm group of length `n` permutations on `n` sites. The dset is silently ignored.
- No precomputation of `(π, v_i)` exists. `parent.space_group` is computed (the R + t pairs) but never used downstream for multi-site permutations.
- `_enumerate_exhaustive` would receive this wrong-cardinality perm group and produce wrong counts on multilattice inputs (if it got past R50.1's validation gate, which it doesn't).

### 7.3 Files that need changes

- `src/types/parent_lattice.jl`: add dset-permutation precomputation; cache `(π, v_i)` per op. Probably as new fields on `ParentLattice` or as a separate helper struct returned by a new accessor.
- `src/types/supercell.jl`: extend `Supercell` to build the n × n_D permutation group when `ndset(parent) > 1`. Either branch on `ndset` or unify via the `n_D = 1` degenerate case.
- `src/Enumlib.jl`: new function `getPermG_multilattice(...)` or extension of `getPermG` signature. The existing `getPermG(h, fixingOps, LG)` (line 283 of Enumlib.jl) is the surgical target.
- `src/enumerate.jl`: `_validate_enumerate_inputs` (regime B branch) flips from "throw R50.2-pending" to "fall through" once R50.2 ships.
- `test/test_hnf.jl`: expand "Supercell — HCP multilattice n=2" to check perm group cardinality + sample action.
- `test/test_enumerate.jl`: new testsets for regime B enumeration with locked reference counts.
