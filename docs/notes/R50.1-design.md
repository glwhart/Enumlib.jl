# R50.1 — Sharpen the multilattice validation + improve error messages (design)

Pre-implementation design doc for the first phase of cross-repo request R50 (JuCE → Enumlib). The full R50 ticket asks for two things; this design covers only the validation/error-message refactor. The actual regime-B algorithmic enablement (HF 2008/2009 multilattice enumeration) is R50.2 — substantial engineering, its own design doc later.

**Ticket reference:** `/Users/glh43/Library/CloudStorage/GoogleDrive-gus.hart@gmail.com/My Drive/Work/codes/JuCE.jl/cross_repo_requests.md` §R50 (updated 2026-05-14 by JuCE-side after the dryrun.jl HCP example surfaced the issue).

**Goal of R50.1.** No behavior change for users who succeed at enumerate today. For users hitting the multilattice / multi-site cases, replace the current single misleading error with three precise ones that distinguish regime A (works), regime B (uniform multilattice — HF 2009 implementation pending), and regime C (heterogeneous sublattices — chunk 6.5 multinomial-restricted).

---

## 1. Background — the three regimes

Per the R50 ticket:

| Regime | `ndset(parent)` | `sites.list` | Algorithm needed | Status today |
|---|---|---|---|---|
| **A. Single-lattice, single-site** | 1 | 1 site, any `BitSet` | HF 2008 | ✅ **Works today.** |
| **B. Uniform multilattice** | ≥ 2 | one site per dset position, **all same `BitSet`** | HF 2008/2009 — no new research | ❌ Blocked. **R50.2 will ship.** |
| **C. Heterogeneous multilattice** | ≥ 2 | one site per dset position, **different `BitSet`s** | HF 2012 §A.1 multinomial-restricted | ❌ Blocked. Chunk 6.5. |

A fourth case is *user-confused* — `ndset(parent) ≠ length(sites.list)`. That's a setup error; should raise distinctly.

---

## 2. Current state — what fires today

`_validate_enumerate_inputs` in `src/enumerate.jl` has **two consecutive checks**:

```julia
if ndset(parent) > 1
    throw(ArgumentError(
        "single-lattice parents only ... Multilattice support ... " *
        "deferred to v0.3."))
end

if length(sites.list) != 1
    throw(ArgumentError(
        "single-site Sites only ... " *
        "Multi-site Sites ... requires the multinomial-restricted algorithm; " *
        "chunk 6.5."))
end
```

Failure modes today:

- **HCP user (regime B)** — uniform binary Sites on a 2-element dset. Hits the **first** check; gets a message saying "deferred to v0.3" — which is wrong (B is HF 2009, not v0.3-scope new research) AND mentions getPermG-related implementation detail that confuses the user.
- **Perovskite user (regime C)** — heterogeneous Sites on a multi-element dset. Hits the **first** check, gets the same "deferred to v0.3" message. Should hit a *different* message pointing at chunk 6.5.
- **Confused user** — single-site parent (`ndset = 1`) with a `Sites` of length > 1. Hits the **second** check; gets the chunk-6.5 message, which is misleading because the user is asking for a per-site-restriction labeling space *that doesn't make geometric sense on a single-site parent.*

## 3. Proposed validation flow after R50.1

Replace the two checks with a single discriminated cascade:

```
nd  = ndset(parent)               # 1 for Bravais, ≥ 2 for multilattice
nsl = length(sites.list)
labels_uniform = nsl >= 1 && all(s.allowed_labels == sites.list[1].allowed_labels for s in sites.list)

if nd == 1
    if nsl != 1
        # User-confused: single-site parent, multi-site Sites.
        throw(ArgumentError("Sites of length $nsl on a single-site parent ..."))
    end
    # Regime A — falls through to the rest of validation.
else  # nd ≥ 2
    if nsl != nd
        # User-confused: dset length ≠ sites length.
        throw(ArgumentError(
            "ndset(parent) = $nd but Sites has $nsl entries; one site per dset " *
            "position is required. Consider `Sites(parent, [0, 1])` " *
            "(R51 convenience constructor)."))
    elseif labels_uniform
        # Regime B — uniform multilattice. R50.2 will ship.
        throw(ArgumentError(
            "Multilattice (uniform sublattices) `enumerate(...)` — HF 2008/2009 " *
            "implementation pending (R50.2). The builder `Sites(parent, $(sites.list[1].allowed_labels))` " *
            "constructs the right Sites object today; the dispatch path to actually " *
            "enumerate it lands in a follow-up chunk."))
    else
        # Regime C — heterogeneous multilattice.
        throw(ArgumentError(
            "Multilattice with per-site `allowed_labels` (heterogeneous sublattices) " *
            "requires the multinomial-restricted algorithm — chunk 6.5. " *
            "For uniform sublattices (same allowed_labels at every dset position), " *
            "see R50.2."))
    end
end

# ... rest of validation (single-site Bravais path) ...
```
